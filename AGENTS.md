# AGENTS.md

Next.js 16 App Router frontend (React 19, TypeScript strict, Tailwind CSS v4) for an installment-management admin panel (سامانه مدیریت اقساط معراجی). Persian (fa-IR) UI. Single package at repo root; no tests, CI, or monorepo tooling. The API is a separate, already-built backend — this repo has no server code.

## Project

- **Domain:** installment management — admin panel for customers, invoices, and their installments.
- **Backend is separate and already implemented** (MongoDB/Mongoose-style documents, JWT auth). No server code lives in this repo.
- **Locale:** the entire UI is **Persian (fa-IR)** — expect an RTL layout.
- **Styling:** **Tailwind CSS v4** (utility-first). No `tailwind.config.*`; theme tokens live in `app/globals.css` under `@theme inline`.

## Commands

- `npm run dev` — Turbopack dev server on :3000
- `npm run build` / `npm start`
- `npm run lint` — bare `eslint` (no args). One file: `npx eslint app/page.tsx`
- `npm run typecheck` — runs `next typegen` (needed because `LayoutProps`/`PageProps` live in `.next/types`) then `tsc --noEmit`
- `npm run format` / `npm run format:check` — Prettier, with `prettier-plugin-tailwindcss` sorting classes. Options live in `prettier.config.mjs`
- No test runner is configured; do not invent `npm test`.

## Non-obvious setup

- `next.config.ts` enables `cacheComponents: true` and `partialPrefetching: true`. With Cache Components on, dynamic data must be wrapped in `'use cache'` (or Suspense) or the build fails — not default Next.js behavior.
- Tailwind v4 is wired through `experimental.turbopack.rules` (`@tailwindcss/turbopack`), not PostCSS.
- Path alias `@/*` maps to the repo root (not `src/`).
- `LayoutProps<"/">`, `PageProps`, and typed `Route` types are generated by Next into `.next/types`; don't hand-write them.
- `front-assent-for-ai/` holds source design assets (logo, avatar, `exit.svg`, Iran Sans font) and is **not** served — copy into `public/` before referencing by URL.

## Backend API

```text
Base URL (dev): http://localhost:4000/api/v1
Swagger UI:     http://localhost:4000/docs/
```

- The OpenAPI JSON is **not** served at a `/docs-json`-style route. It is inlined into `http://localhost:4000/docs/swagger-ui-init.js` as `options.swaggerDoc` — fetch that file to read machine-readable paths and schemas.
- The dev backend listens on `:4000`; the frontend keeps the `next dev` default `:3000`, so there is no port clash. Keep the API base URL configurable (env var), not hard-coded.

### Response envelope

Every endpoint wraps its payload in a single envelope:

```ts
{
  (success, timestamp, statusCode, errorCode, message, data, error, errorDetails);
}
```

- Success: `success: true`, `error: null`, payload under `data`.
- Error: `success: false`, `errorCode` (e.g. `BAD_REQUEST`), a human-readable `message`, and `errorDetails` (an array of `{ field, message }` for validation errors, otherwise `null`).

### Pagination

The `search` endpoints return `data` as `{ result, meta }` — **not** mongoose's `docs` key:

```ts
{
  result: Item[],   // the current page of documents
  meta: {
    totalDocs, limit, page, totalPages, pagingCounter,
    hasPrevPage, hasNextPage, prevPage, nextPage
  }
}
```

### Errors

On failure the envelope is `success: false`, `data: null`, with a code in `errorCode`:

| HTTP | `errorCode`             | Meaning                                                                |
| ---- | ----------------------- | ---------------------------------------------------------------------- |
| 400  | `BAD_REQUEST`           | invalid input / validation; `errorDetails` is a `{ field, message }[]` |
| 400  | `ERROR_OTP_INVALID`     | `verify-otp`: wrong OTP                                                |
| 400  | `ERROR_TOKEN_REQUIRED`  | `refresh`: refresh token missing or invalid                            |
| 401  | `UNAUTHORIZED`          | missing or invalid bearer token                                        |
| 401  | `INVALID_CREDENTIALS`   | `send-otp`: phone number not registered                                |
| 403  | `FORBIDDEN`             | role not allowed for the route                                         |
| 404  | `NOT_FOUND`             | resource not found (e.g. invoice)                                      |
| 404  | `USER_NOT_FOUND`        | user not found                                                         |
| 429  | `TOO_MANY_REQUESTS`     | `send-otp` rate limited                                                |
| 500  | `INTERNAL_SERVER_ERROR` | server error                                                           |

Validation example (400):

```json
{
  "success": false,
  "timestamp": "2026-01-01T00:00:00.000Z",
  "statusCode": 400,
  "errorCode": "BAD_REQUEST",
  "message": "Bad Request",
  "data": null,
  "errorDetails": [
    { "field": "phoneNumber", "message": "Phone number must be at least 10 digits" }
  ]
}
```

- `errorDetails` is **sometimes a plain string** rather than an array — e.g. upload/delete errors return `"حجم فایل بیشتر از حد مجاز (۵ مگابایت) است."`. Handle both types.

### Auth

- JWT bearer: send `Authorization: Bearer <token>` on every endpoint except `Auth`.
- Token strings **already include** the `Bearer ` prefix (access/refresh) — don't add it twice.
- Login is OTP-based: `POST /auth/login/send-otp` → `POST /auth/login/verify-otp` → `data = { access, refresh }`; renew with `POST /auth/refresh` `{ refreshToken }`.
- Roles: `SUPER_ADMIN`, `SELLER`, `ACCOUNTANT`, `USER`.

### Search & filter semantics

- `/invoice/search` — required `search`, `limit`, `page`. `search` matches user name/lastName/nationalId/phone OR product details. `fromDate`/`toDate` filter the invoice `start_date`.
- `/installments/search` — required `limit`, `page`. `status` ∈ `all` | `paid` | `overdue` | `pending` (default `all`); `fromDate`/`toDate` filter the due date; **when `status=overdue`, `fromDate`/`toDate` are ignored**; `user` filters by user ObjectId.
- The `fromDate`/`toDate` filter params are **Gregorian** `YYYY-MM-DD` — unlike `InvoiceInput.start_date`, which is a Jalali string.

### Behaviors & gotchas

- `SUPER_ADMIN` reaches every route and `SELLER` reaches users plus products; `ACCOUNTANT` can only read products. `USER` is a customer account: it is rejected at login and only opens the public invoice link.
- `send-otp` only works for a phone number **already registered** (otherwise 401 `INVALID_CREDENTIALS`); OTP sending is rate limited (429).
- `installments/paid` only succeeds when the installment is `status=pending` **and** `paymentReceipt=null`; it sets `paidAt` and moves the receipt file from `uploads/temp` to the main uploads folder.
- `file/send`: the multipart field must be named exactly `file`; only `image/jpeg`, `image/png`, `image/webp`; max 5 MB. Validation failures carry a string `errorDetails` (no file / too large / invalid format).
- `file/delete`: 400 if the temp file is missing or already deleted.
- Swagger quirk: path parameters on `/users/find/one/{id}`, `/users/update/{id}`, `/users/remove/{id}`, and `/invoice/find/one/{invoiceId}` are rendered without a name in the spec; the path segment is a Mongo ObjectId.

### Key models

- **User** — `name`, `lastName`, `nationalId` (10 digits), `role`, `phoneNumbers { primary, secondary? }`, `residentialAddress`, `employmentDetails { occupation, workplace }`, `guarantorContact`, `identityDocuments { nationalCardImage, otherDocuments[] }`.
- **Invoice** — auto `name` (`{nationalId}-{seq}`), `user` (id or populated), embedded `products[]` and `pledge[]`, generated `installments[]`, `downPayment`, `start_date` (Jalali string), `installmentCount` (1–60); virtuals `totalAmount`, `installmentsStatus { pending, paid }`.
- **Product** (embedded) — `name`, `pictures[]` (the field is `pictures`, not `images`), `price`, `details`, optional `imei`.
- **Pledge** (embedded) — `name`, `picture`, `details`.
- **Installment** — `invoiceId`, `user`, `no`, `amount` (principal), `amountWithInterest`, `status` (`pending` | `paid` | `overdue`), `paymentReceipt`, `dueDate` + `dueDateJalaly`, `paidAt`, and virtuals `daysOverdue`, `latePenalty`, `payableAmount`.

### Domain notes

- **Dates & amounts.** Dates are Jalali/Persian: `InvoiceInput.start_date` is a string like `"1405/08/25"`; installments expose `dueDateJalaly` alongside the raw `dueDate`. `amount`/`price` are plain numbers — the currency unit is not stated in the spec; confirm before formatting.
- **IDs** are MongoDB ObjectId hex strings (24 chars).
- **Field-name gotchas** (do not "fix" these — they match the backend): the check-unique responses are `exitingPhone` / `exitingNationalId`, and product images use `pictures`.
- **Upload flow:** `POST /file/send` → `data.filePath` (filename) → later pass that filename as `Installment.paymentReceipt` via `POST /installments/paid`; delete abandoned temp files with `POST /file/delete`.
